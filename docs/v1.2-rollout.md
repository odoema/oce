# OCE V1.2 Rollout Plan

## Phase 1 — Delivery boundary

- provider-neutral adapter contract
- dry-run delivery mode
- idempotent batch processing
- provider response logging

## Phase 2 — Compliance controls

- unsubscribe URL/header support
- suppression synchronization
- bounce and complaint handling
- consent audit trail

## Phase 3 — Production verification

- verify sending domain and sender identity
- send one controlled test
- verify delivery and lifecycle events
- confirm suppression behavior
- confirm duplicate prevention

## Phase 4 — Controlled campaign operation

- keep application batches at 250 or below
- respect provider quotas and rate limits
- use scheduled sending windows
- monitor errors and complaints
- pause immediately on abnormal bounce/complaint rates

## Phase 5 — Analytics

Track at minimum:

- queued
- attempted
- accepted
- delivered
- bounced
- complained
- unsubscribed
- failed
- suppressed

No production bulk send should be enabled merely because the code path exists. Activation requires the operator to verify consent, sender authentication, unsubscribe behavior, suppression, and provider delivery results.
